# v0.4.0 — Decision Judge → Evidence Gate (pre-registration)

**Status of this document:** sections 1–6 were written and committed **before any v0.4.0 model run**
(including the pilot). They must not be edited after results are seen. Results are appended in
section 7 and in `benchmark-results/sample/v0.4/`.

## 1. Why

v0.3.0 closed the blind-first hypothesis (blindness gave no advantage). The main problem it found was
critic bias: ~61% false interventions on correct proposals at ~100% defect recall (97% of
interventions in the main modes hit correct proposals). The experimental `decision_judge` prompt cut
false interventions by ~36 pp at full recall but stayed far from usable. v0.4.0 is **one final
architectural experiment**: a single judge that may only intervene with **mechanical evidence**.
Single agent, no swarm.

## 2. Design (`evidence_gate`, benchmark mode)

- The judge sees the task, the proposed plan + patch, and read-only access to a small repository
  snapshot **with the patch already applied**.
- No material defect → `KEEP`. If it suspects one it must emit one verifiable claim:
  `{claim, severity, evidence_needed, verification, evidence_refs, result: confirmed|not_confirmed|unable_to_verify, verdict: KEEP|WARNING|MODIFY|REPLACE}`.
- Tools (OpenRouter tool calling), all sandboxed to the snapshot directory: `search` (regex grep),
  `find_symbol` (definitions/references), `read_file` (size-capped), `inspect_config`
  (package/config/schema files + test allowlist), `run_test` (one EXISTING test file from the
  allowlist, `node --test`), `typecheck` (`tsc --noEmit` on the snapshot tsconfig). No editing, no
  arbitrary commands, child processes get a minimal environment (no API keys), timeouts, output caps,
  tests/typecheck run in a throw-away copy. Hard cap: **8 tool calls** per review, **80,000 tokens**
  per review, 4,000 tokens per call, 300 s timeout.
- **The harness, not the model, validates "confirmed".** A claim counts as confirmed only if its
  `evidence_refs` cite a tool output from the same session (`T1`, `T2`, … ids or `file:line`) that
  contains a mechanical artifact:
  - a failing test (`run_test` exit ≠ 0 with `not ok` lines), or
  - a typecheck error (`file(line,col): error TSxxxx`), or
  - a concrete search/find_symbol hit `file:line` **outside the lines added by the proposed patch**
    (a hit on the patch's own lines only quotes the proposal back). If `file:line` locations are
    cited, a cited search must have returned exactly that location.
  Otherwise "confirmed" is downgraded to "not_confirmed".
- MODIFY/REPLACE survive only with a validated confirmed claim. Every other MODIFY/REPLACE
  (not_confirmed, unable_to_verify, downgraded) is forced to **WARNING**. KEEP/WARNING pass unchanged.
- Known limitation, stated in advance: the harness checks that an artifact exists and is cited, not
  that it is *relevant* to the claim. A model can cite an unrelated failing test or search hit. The
  search-hit rule above reduces this; the case design (correct proposals have green tests and a
  clean typecheck) makes irrelevant failing tests impossible on correct cases.
- Prompt + tool definitions are frozen by hash (`tests/prompt-freeze.test.ts`, `evidence_gate`).
  v0.3.0 modes and prompts are unchanged. Baselines on the same cases: `decision_judge` (v0.3.0
  prompt, single pass, no tools) and optionally `proposal_first`; they get the same text (task, plan,
  patch, file list, test file names) but no tools and no gate.

## 3. Cases

`benchmark/repo-cases/<nn-id>/{case.json, repo/}`: 20 tiny zero-dependency JavaScript projects
(ESM, JSDoc types checked by `tsc --noEmit` with `checkJs`, tests with `node:test`, nothing installed
at review time). `repo/` is the state after the proposed patch; the patch is in
`input.proposed_solution`. Ground truth is in `case.json`, outside `repo/`, so the tools cannot reach
it (tested), and leak tests check that no ground-truth text reaches any model request.

| group | n | ids |
|---|---|---|
| defect, confirmable by a failing existing test | 3 | slugify-diacritics, page-based-pagination, retry-jitter |
| defect, confirmable by typecheck | 3 | money-object-signature, config-field-rename, refund-ledger-status |
| defect, confirmable by search (file:line elsewhere) | 2 | remove-xml-exporter, drop-legacy-id-column |
| defect, NOT mechanically confirmable (perf/architecture/security) | 3 | live-dashboard-aggregation, in-memory-rate-limit, fast-password-hash |
| correct proposal (several tempt nitpicks) | 9 | debounce-clear-timer, limit-param-validation, bounded-lru-memoize, csv-rfc4180-quoting, new-checkout-flag, rename-date-helper, inclusive-end-date, email-domain-case, notify-allsettled |

A test (`tests/evidence.test.ts`) verifies the labels mechanically: test-defect snapshots have a
failing test, typecheck-defect snapshots have tsc errors, all other snapshots (search defects,
untestable defects, correct) have green tests and a clean typecheck. All cases are synthetic and
written by the repository author; the author also wrote the ground truth (single annotator).

## 4. Metrics (mechanical, no LLM judge)

- **Intervention** = final verdict MODIFY or REPLACE. WARNING is **not** an intervention (the change
  proceeds, with a note). INSUFFICIENT_EVIDENCE (baselines) is not an intervention.
- **Recall (testable)** = intervention rate on the 8 mechanically confirmable defect cases.
- **Recall (untestable)** = intervention rate on the 3 untestable defect cases — reported separately,
  not part of the criterion. "Flagged" (MODIFY/REPLACE/WARNING) is reported as a secondary number.
- **False intervention (FI)** = intervention rate on the 9 correct cases. WARNING rate on correct
  cases is reported separately.
- Gate statistics: claims, model-claimed "confirmed", validated, **downgraded**, verdicts forced to
  WARNING, and the **ungated counterfactual** (the model's own verdict without the gate).
- Rates over successful runs with 95% Wilson intervals; failures reported. Runs of the same case are
  correlated, so Wilson intervals over runs are optimistic; paired case-bootstrap differences vs the
  baseline are descriptive only.
- Cost: OpenRouter-reported `usage.cost` per call (fallback: tokens × list price), appended to a
  shared ledger (`benchmark-results/sample/v0.4/spend.jsonl`) that includes the pilot and failed
  attempts.

## 5. Pre-registered success criteria (`benchmark/evidence/criteria.ts`)

Applied to `evidence_gate`, **per model**, on point estimates:

| label | rule |
|---|---|
| **continue** | recall(testable) ≥ 90% **and** FI ≤ 20% |
| **archive whole project** | FI ≥ 40% |
| **inconclusive** | anything else |
| inconclusive (failures) | > 10% of that model's evidence_gate reviews failed after retries |

Project-level verdict: **continue** only if both models are "continue"; **archive** only if both
models are "archive"; otherwise **inconclusive**. Wilson intervals are reported next to every
number; with n ≈ 8–9 cases × few runs they are wide, and the report says so instead of over-reading
point estimates.

## 6. Models and budget

Models chosen by the maintainer: `z-ai/glm-5.3-flash` and `qwen/qwen3.8-flash` (OpenRouter), no
substitutes. Checked on 2026-10-04 via `GET /api/v1/models`: both exist and list `tools`
support; list prices per 1M tokens: glm-5.3-flash $0.15 prompt / $0.50 completion, qwen3.8-flash
$0.15 / $0.47. Reasoning settings: provider default (not set). Total budget for all v0.4.0 runs:
≈ $1.00; plan ≤ $0.85 after a pilot (2–3 cases × 1 run × both models × evidence_gate +
decision_judge); hard stop at $0.95 cumulative (enforced by the runner from the ledger).

## 7. Results

Raw data: `benchmark-results/sample/v0.4/` (`main-glm-5.3-flash/`, `main-qwen3.8-flash/`,
`pf-glm-5.3-flash/`, pilots, `spend.jsonl`, `SUMMARY.md`). 20 cases × 5 runs × {evidence_gate,
decision_judge} per model; `proposal_first` 1 run for glm only (budget). Rates are over successful
runs, value [95% Wilson CI] (k/n). Runs of one case are correlated, so the intervals overstate
precision (the real n is 8 testable-defect, 3 untestable-defect and 9 correct cases).

| model | mode | recall testable | recall untestable | FI on correct | WARNING on correct | failed |
|---|---|---|---|---|---|---|
| glm-5.3-flash | evidence_gate | 95% [84–99] (38/40) | 20% [7–45] (3/15) | 0% [0–8] (0/45) | 2% (1/45) | 0/100 |
| glm-5.3-flash | decision_judge | 62% [46–75] (24/39) | 100% [80–100] (15/15) | 5% [1–16] (2/43) | 0% | 3/100 |
| glm-5.3-flash | proposal_first (1 run) | 75% [41–93] (6/8) | 100% (3/3) | 11% [2–44] (1/9) | 0% | 0/20 |
| qwen3.8-flash | evidence_gate | 100% [91–100] (40/40) | 8% [2–35] (1/12) | 0% [0–9] (0/37) | 3% (1/37) | **11/100** |
| qwen3.8-flash | decision_judge | 84% [70–93] (32/38) | 100% [79–100] (14/14) | 14% [6–29] (5/35) | 0% | 13/100 |

Recall by defect kind (evidence_gate vs decision_judge): test 100% vs 100% (both models);
typecheck glm 93% vs 40%, qwen 100% vs 64%; search glm 90% vs 40%, qwen 100% vs 89%.

Gate statistics (evidence_gate):
- glm: 51 claims, 43 "confirmed" by the model, 41 validated, **2 downgraded** (both on untestable
  defects, both REPLACE → WARNING). qwen: 53 claims, 41 confirmed, 41 validated, **0 downgraded**.
- The ungated counterfactual (the model's own verdict) is almost identical to the gated result (glm
  untestable recall 33% ungated vs 20% gated; everything else equal). **Most of the effect comes from
  the evidence prompt, not from the harness forcing verdicts**: under this prompt the models
  themselves choose KEEP/WARNING when they cannot produce evidence.
- Validated evidence by type: glm failing_test 15, typecheck 14, search hit 26; qwen 15 / 15 / 28.

**Pre-registered verdict (section 5):** glm-5.3-flash → **continue** (recall 95% ≥ 90%, FI 0% ≤ 20%);
qwen3.8-flash → **inconclusive (failures)** (11% of evidence_gate reviews failed with upstream HTTP 429
after retries and two `--resume` attempts; on its successful runs the rates would satisfy "continue":
recall 100%, FI 0%). **Project verdict: inconclusive.**

### Caveats that limit what this shows (read before the verdict)

1. **The new cases do not reproduce the v0.3.0 problem.** On these cases the decision_judge baseline
   already has a low FI (glm 5%, qwen 14% in the final report, 16% before the resume of failed records; glm proposal_first 11% on 1 run), compared with ~61%
   (decision_judge) and ~97% (proposal_first) in v0.3.0. The correct proposals are probably not
   tempting enough (small, self-contained diffs with tests). So evidence_gate's 0% FI is **not strong
   evidence that the gate removed false interventions**; the paired FI reduction vs decision_judge is
   +5 pp [0, +15] (glm) and +14 pp [0, +43] (qwen).
2. **The clearer effect is higher recall on typecheck/search defects** (repo access lets the judge
   find the broken caller / config / query that the patch text does not show): testable recall
   +33 pp [+8, +62] (glm), +16 pp [0, +37] (qwen) vs decision_judge.
3. **The cost is a collapse of recall on untestable defects** (perf / architecture / security:
   per-request full scan, per-replica rate limiting, fast password hash): glm 20%, qwen 8% vs 100%
   for decision_judge. They mostly end as WARNING (glm 9 of the 12 non-KEEP, qwen 11 of 12), which is largely the model's own choice under the
   evidence prompt (the harness forced only 2 verdicts). A real deployment would let these through
   with a note.
4. **The gate's validation is shallow** (the risk named in section 2). Post-hoc audit, not
   pre-registered: all 4 "validated" interventions on untestable cases (glm 3, qwen 1) were validated
   by irrelevant search hits on *unchanged* lines of the patched file (e.g. `const ITERATIONS =
   210_000;`). Treating those as WARNING gives untestable recall 0% for both models. No irrelevant
   validation occurred on correct cases, but correct cases offered nothing tempting to cite.
5. Single author for cases and ground truth; 20 synthetic cases; small n; two cheap models only.

### Deviations from sections 2–6 (documented, not edited above)

- After the pilot, harness-only fixes (prompt unchanged, hash `27b99c0914be4874`): per-call token
  cap 4,000 → **8,000** (glm truncated its final answer), normalisation of a flattened `claim`
  object, and a provider bug in reading the HTTP error body. Pilot records are kept
  but are not part of the main tables.
- The ledger hard stop was per process at first (two parallel processes); a key-usage watchdog
  (kill at $0.85 real spend) guarded the run, and the ledger now re-reads the shared file.
- qwen's failed records were retried with `--resume` (successful records were never re-run); the
  final qwen report was regenerated from the checkpoint without new calls.

### Cost

OpenRouter key usage for all v0.4.0 calls (pilots, main runs, retries, timeouts): **$0.80**
(authoritative: the key's usage delta). The internal ledger shows $0.678 because aborted/timed-out
requests (frequent with qwen's decision_judge at the 120 s timeout) are billed but report no usage.
Per review (ledger): evidence_gate glm $0.0020, qwen $0.0010; decision_judge glm $0.0016,
qwen $0.0016; proposal_first glm $0.0010. Evidence_gate used ~10–12k tokens per review (4.5–5.1 tool
calls on average) vs ~4–5k for decision_judge, but at these prices it costs about the same, because
decision_judge spends many reasoning tokens.
